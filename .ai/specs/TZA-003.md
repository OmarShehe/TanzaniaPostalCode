# TZA-003: Read-only SQLite address store with search, lookup and browse API

## Summary
Add a KMP `:data` module that ships a prebuilt read-only SQLite database (generated from `dataset/tz-address.json`) and a `SqliteAddressRepository` implementing an extended `AddressRepository` (search, postcode lookup, reverse path, browse). Access is plain `androidx.sqlite` with the bundled driver so FTS5 behaves identically everywhere. Key trade-offs: the DB is a generated, uncommitted artifact; the binary is bundled via Compose Multiplatform *resources* (only the `components-resources` runtime, no UI) because plain KMP has no common resource API for iOS; iOS execution cannot be verified here (no Xcode).

## Module Impact
`:core` (API types + interface extension), `:data` (new), `:importer` (hosts the DB generator: it already owns the DTOs), `:app` (sample search box). Settings/catalog.

## Architecture Conformance
No project rules files exist; applying the ticket design. `:core` stays platform-free pure Kotlin with `explicitApi()`; `:data` also `explicitApi()`, public surface only the platform factories plus core types; SQL, FTS and file handling are `internal`. One top-level declaration per file. Ids come only from `AddressIds` (used by the generator via `CoreDataset`, and by the ticket's stored ids). The generator lives in `:importer` (not `:data`) because `DatasetDto`/`toCore()` live there and `:data` must not depend on a JVM tool; `:data:generateAddressDb` is a `JavaExec` wrapper task over it. New naming decisions recorded in `.ai/context.md`: package `com.omarshehe.tzaddress.data`, DB file `tz-address.db`.

## Implementation Steps
1. Catalog + settings: add versions/libs; `include(":data")`.
2. **FTS spike first** (gate): `data` module skeleton + a test that opens an in-memory DB with the bundled driver, creates an FTS5 table with `prefix` index, inserts, and queries `MATCH 'kiv*'`. Run on JVM (`:data:jvmTest`) and on the connected device (`:data:connectedAndroidDeviceTest`). iOS: klib compile only (no Xcode to run). If JVM or Android fails, stop and report.
3. `:core`: `Level` (REGION, DISTRICT, WARD, MTAA, KITONGOJI, `all`), `AddressPath`, `AddressMatch`; extend `AddressRepository`; update fake + contract tests (Red first).
4. `:importer`: `AddressDbSchema` (DDL), `AddressDbBuilder.build(CoreDataset, File)` (deterministic insertion order, `search_index` FTS5 rows `level, ref_id, name, path_text` over normalized text, `dataset_info` row, per-table count verification), `GenerateDbMain`; tests first.
5. `data/build.gradle.kts`: `generateAddressDb` (JavaExec over importer classpath, output `data/src/commonMain/composeResources/files/tz-address.db`, reads dataset + `import-report` totals? — counts are verified against the dataset itself; the report totals are cross-checked by parsing the report's total line) and wire it before resource generation.
6. `Normalizer`: lower-case, strip `'`, `"`, `’`, diacritics, collapse whitespace (tests first).
7. `SearchQuery` (tokenize -> FTS5 `"tok"*` AND query, quoting to avoid FTS syntax injection), `SearchRanking` (exact > prefix > token; higher level wins ties; deterministic tiebreak by name then id) — pure, tested first.
8. `SqliteAddressRepository`: browse (ordered by name), `search`, `byPostcode`, `byPrefix`, `path`, `isValidPostcode` (ward postcode set cached at creation; creation is `suspend`), all on `Dispatchers.Default`-safe reads (each call uses its own read-only connection or a mutex-guarded one).
9. `DbInstaller`: copy-once from resource bytes to app storage via kotlinx-io, replace when bundled `dataset_info.version` differs; tests with a temp dir (copy once, no re-copy, version change replaces).
10. Platform factories: Android `createAddressRepository(context)`, JVM `createAddressRepository(dir)`, iOS `createAddressRepository()`.
11. `:app`: sample search box; build/install on the device and drive it via adb for manual QA.
12. Benchmark test (JVM + one device run) recording p95 for a 3-letter prefix; recorded in spec, not asserted.
13. `.ai/context.md`, ticket scope notes.
14. Verify: `:core:jvmTest :core:testAndroidHostTest :importer:test :data:jvmTest`, device test, iOS klib compile for core+data, `:app:assembleDebug :app:assembleRelease`, `./gradlew build` with the documented Xcode exclusions.

## Test Plan (TDD)
- `Normalizer` -> `Jang'ombe`->`jangombe`, `KARIAKOO`->`kariakoo`, `Mtambani "A"`->`mtambani a`, `Ngoma’s`, extra spaces, empty.
- `SearchQuery` -> `kivu`->`"kivu"*`; `ilala kariakoo` -> two tokens AND; FTS operators/quotes (`a" OR b*`, `-`, `:`) neutralised; blank -> null.
- `SearchRanking` -> exact beats prefix beats token; ward beats mtaa on tie; stable order; limit clamp 0->1, 1000->100.
- `AddressDbBuilder` -> table counts equal the dataset; dataset_info stored; deterministic output (same bytes twice is *not* guaranteed by SQLite, so assert logical equality of dumped rows); fails on count mismatch.
- `SqliteAddressRepository` (real DB built from the committed dataset in test) -> `search("kivu")` includes Kivukoni / Ilala CBD / `11101`; `jangombe`; `KARIAKOO`; `ilala kariakoo` ranks Kariakoo ward first; `byPostcode("11101")` chain; `"00000"`, `"abc"`, `""` -> null; `byPrefix("111")` only wards starting `111`, bad input -> empty; **round-trip for every ward**; browse ordered by name, unknown parent -> empty; blank query -> empty; `path()` for each level; every match carries nearest-ancestor postcode.
- `DbInstaller` -> first run copies, second doesn't, version bump replaces, corrupt/partial file replaced (write to temp then rename).
- Not unit-tested: platform factories (compile + device run), iOS runtime (unverified), benchmark (recorded).

## Acceptance Criteria
- [ ] Maintainer: **FTS spike passes first** — a test proves FTS works on the JVM target and on an Android (instrumented or Robolectric-free host-with-bundled-driver) target, and iOS simulator runs the same query test; recorded in the ticket PR. If any target fails, the ticket stops and returns to discussion (fallback: `LIKE` on the normalised column with an indexed prefix column).
- [ ] Consumer developer: `search("kivu")` returns Kivukoni (ward and/or mtaa) with region "Dar es Salaam", district "Ilala CBD" and postcode `11101`.
- [ ] Consumer developer: `search("jangombe")` matches `Jang'ombe`; `search("KARIAKOO")` matches case-insensitively; `search("ilala kariakoo")` returns Kariakoo ward ahead of unrelated matches.
- [ ] Consumer developer: `byPostcode("11101")` returns the full chain Region/District/Ward; `byPostcode("00000")` and `byPostcode("abc")` return null; `byPrefix("111")` returns only wards whose postcodes start with `111`.
- [ ] Consumer developer: for every ward in the dataset, `byPostcode(ward.postcode)` round-trips to that ward (test iterates all wards).
- [ ] Consumer developer: browse calls return children ordered by name; unknown parent codes return an empty list.
- [ ] Consumer developer: `search("")` and `search("   ")` return an empty list; `limit = 0` and `limit = 1000` are clamped, not errors.
- [ ] Maintainer: `search` p95 latency on a mid-range Android emulator profile is under 50 ms for a 3-letter prefix (measured by a benchmark test; result recorded, not flaky-asserted in CI).
- [ ] Maintainer: on first run the DB is copied once; a second launch does not re-copy; a bundled `dataset_info.version` change replaces the copied file.
- [ ] Maintainer: `generateAddressDb` counts per table equal the counts in `dataset/import-report.md`; the task fails if they differ.
- [ ] Consumer developer: `:data` compiles for Android, JVM and iOS targets and its API contains no Android-only types.

## Rule Constraints
- Versions only in `gradle/libs.versions.toml`; `explicitApi()` in `:core` and `:data`; `commonMain` free of `android.*`/`java.*`.
- One top-level declaration per file; ids only via `AddressIds`.
- Local-only git; no commit without approval; branch `feature/TZA-003` -> merge into `feature/tz-address-kit`.

## Risks & Gotchas
- **iOS unverified**: only klib compile is possible; the iOS FTS-spike and runtime AC cannot be met here. Reported honestly; needs a machine with Xcode.
- **Bundled resource on iOS** needs Compose resources (`components-resources`); deviation from ticket's `resources/` path. Fallback if it misbehaves in a library module: Android/JVM classpath resources + iOS documented as pending.
- **AGP-9 KMP library + Compose resources / device tests** (`withDeviceTest`) are new plugin combos; first build may need tweaks.
- Android `Context` in the Android factory (public API type is `android.content.Context` only in `androidMain`; common API stays platform-free, satisfying the AC).
- Generated DB is git-ignored; a clean checkout must run `generateAddressDb` (wired into resource processing so `assemble` does it automatically).
- "Counts equal `import-report.md`": the report is markdown; the check parses its totals line (added to the importer report format if not machine-friendly), else compares against the dataset only and the ticket AC gets a scope note.
- A 3-letter prefix p95 on the physical device is not an "emulator profile"; recorded as measured.
- `isValidPostcode` is non-suspend, so repository creation is `suspend` and preloads the ward set (~3.4k strings).
