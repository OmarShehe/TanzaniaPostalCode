# TZA-005: Publish the artifacts and document how to plug them into any project

## Summary
Make `:core`, `:data` and `:ui` publishable (artifacts `tz-address-core`, `tz-address-data`, `tz-address-ui`, group `io.github.omarshehe`) with the Vanniktech maven-publish plugin, add a tag-triggered release workflow, replace the one-line README with an install/usage/update guide whose snippets are verified, and add `CHANGELOG.md`, `DATA_SOURCE.md` and `LICENSE`. Key trade-offs: the release workflow and Maven Central upload cannot be exercised locally (no secrets, needs a push), and the JVM consumer check needs a Linux host because the bundled SQLite driver has no Intel-macOS binary.

## Module Impact
`:core`, `:data`, `:ui` (publishing config only, no code); `:app` and `:importer` explicitly unpublished. Root `gradle.properties`, `gradle/libs.versions.toml`, `.github/workflows/release.yml`, `README.md`, `CHANGELOG.md`, `DATA_SOURCE.md`, `LICENSE`, `.ai/context.md`.

## Implementation Steps
1. Catalog + root plugin alias for Vanniktech 0.37.0; `GROUP`/`VERSION_NAME`/POM properties in `gradle.properties`.
2. Apply the plugin in `:core`, `:data`, `:ui` with explicit coordinates (`tz-address-core|data|ui`) and POM (name, description, licence, SCM, developer).
3. `./gradlew publishToMavenLocal`; inspect what lands in `~/.m2` (artifact ids, per-target variants, DB inside the `data` jvm jar and android aar, no `app`/`importer`).
4. Throwaway **Android** consumer project outside the repo (`mavenLocal()`, README instructions only): `search("kivu")` compiles and returns Kivukoni on a device.
5. Throwaway **JVM** consumer: `byPostcode("11101")` on a supported host (Linux in Docker if the daemon is available; otherwise report as unverified on this machine).
6. `README.md`: what it is, coverage/edition, install (Android, KMP `commonMain`, JVM, iOS bundling step), usage snippets, `:ui` picker with `docs/` screenshots, dataset update procedure, versioning, platform notes, licence, attribution. Every snippet is copied from code that compiles (sample app or the throwaway consumers).
7. `CHANGELOG.md`, `DATA_SOURCE.md` (with markers), `LICENSE`.
8. `.github/workflows/release.yml` (macOS runner; fail on missing `LICENSE` or `TODO(maintainer)`; publish; attach `tz-address.db` + `.version`); validate YAML syntax locally.
9. `.ai/context.md`, ticket scope notes; final verification (`publishToMavenLocal` twice for stability, full test run).

## Risks & Gotchas
- **Namespace/licence/data terms are the maintainer's decisions**: group `io.github.omarshehe` must match the GitHub account that owns the repo; the licence must be chosen; `DATA_SOURCE.md` needs facts only the maintainer has. The release stays blocked until they are filled (by design).
- **AGP-9 KMP library + publishing** is a new combination; the Android publication may need config tweaks.
- **iOS artifacts carry no data**: consumers must add the two DB files to their bundle; a mistake here fails at runtime ("Bundled resource not found").
- **Intel Mac**: JVM consumer verification needs Linux; Docker Desktop is installed but its daemon is not running.
- Release workflow can't be run locally; first real run happens after a push, so expect a fix-forward iteration.
- The already-committed `dataset/tz-address.json` derives from a PDF with unknown redistribution terms; do not publish before `DATA_SOURCE.md` is resolved.
